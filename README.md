# Исследовательский анализ данных (EDA) маркетплейса Olist (Python)

Проект по глубокому исследованию, аудиту и очистке данных бразильского маркетплейса Olist с использованием библиотек Python (Pandas, NumPy) и инструментов визуализации.

Этот проект является **первым этапом** сквозного анализа данных. Его цель — понять структуру данных, выявить скрытые проблемы (аномалии, пропуски, дубликаты) и определить логические связи между таблицами перед загрузкой в базу данных и построением BI-дашборда.

## 🎯 Задачи проекта
1. Оценить качество исходных данных (9 CSV-файлов).
2. Выявить и проанализировать пропущенные значения (Null/NaN) и дубликаты.
3. Исследовать связи между таблицами (по каким ключам они соединяются).
4. Очистить данные и привести их к корректным типам (даты, числа).
5. Сделать выводы о пригодности данных для дальнейшего анализа.

## 💡 Ключевые выводы и инсайты (Data Quality)
В ходе исследования были выявлены следующие особенности датасета:

1. **Специфика связей `customer_id` и `customer_unique_id`:** В датасете клиентов один и тот же покупатель может иметь несколько `customer_id` (по одному на каждый заказ), но объединяется под одним `customer_unique_id`. Это важнейший инсайт для корректного подсчета уникальных клиентов в будущем.
2. **Пропуски в датах доставки:** Около 3% записей в таблице заказов не имеют даты доставки (`order_delivered_customer_date`). Анализ показал, что большинство из них — это заказы со статусами `shipped`, `canceled` или `unavailable`, что логично. Однако было найдено 8 заказов со статусом `delivered`, у которых отсутствует дата — это требует внимания при анализе.
3. **Пропуски в отзывах:** Около 80% отзывов не имеют заголовка (`review_comment_title`), а около 58% — самого текста (`review_comment_message`). При этом оценка (`review_score`) присутствует всегда, что позволяет строить графики удовлетворенности без потери данных.
4. **Товары без категорий:** Обнаружено 611 товаров с полностью отсутствующей информацией о категории. Было принято решение не удалять их, а оставить для дальнейшего анализа (с заменой на метку `Unknown` на этапе SQL-очистки).
5. **Дубликаты:** Прямых полных дубликатов строк не обнаружено. Однако в таблице отзывов есть записи с повторяющимися `review_id` (с одинаковым содержанием), которые впоследствии были обработаны на этапе SQL.
